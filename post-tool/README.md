# 店舗情報管理付き Google投稿コンテンツ生成ツール

合同会社Four Seasons向けのツールです。顧客・ブランド・店舗の情報を登録し、その情報だけを使って、Google投稿用の **画像用キャッチコピー・日本語投稿文・英語投稿文** を1セットで作ります。生成した文章は担当者が確認・編集してから使います。

- 初期版の範囲は、登録・生成・編集・保存・コピーまでです。
- Googleビジネスプロフィールへの自動投稿は行いません。外部に投稿する機能そのものを持っていません。

## 起動方法

Node.js 22.13 以上が必要です。データベースには Node.js に組み込みの SQLite を使います。

```bash
cd post-tool
npm install
npm run seed      # 任意：架空のテストデータ（2顧客・3店舗）を投入
ANTHROPIC_API_KEY=（APIキー） npm start
# → http://127.0.0.1:3000
```

| 環境変数 | 内容 |
|---|---|
| `ANTHROPIC_API_KEY` | AI生成（Claude）用のAPIキー。未設定の場合はデモ生成（テンプレート）のみ使えます。ソースコードには保存しません。 |
| `ANTHROPIC_MODEL` | 使用するモデル。初期値は `claude-opus-5-5` |
| `ANTHROPIC_EFFORT` | 生成の丁寧さ（`low`〜`max`）。初期値は `high` |
| `APP_PASSWORD` | 設定すると画面全体にパスワード認証（Basic認証）がかかります |
| `PORT` / `HOST` | 待ち受けポートとホスト。初期値は `3000` / `127.0.0.1` |
| `DATA_DIR` | データの保存先。初期値は `./data` |

## 画面構成

| タブ | できること |
|---|---|
| 投稿作成 | 店舗を検索して選び（複数選ぶと一括生成）、投稿内容を入力 → 生成前の確認 → 生成 → 編集・保存・コピー |
| 投稿案一覧 | 店舗・テーマ・状態・作成日・キーワードで検索。編集、状態変更、複製、履歴、CSV出力 |
| 顧客・店舗情報 | 顧客 → ブランド → 店舗 → メニューの階層で、登録・編集・削除・履歴確認 |
| CSV・バックアップ | 顧客・ブランド・店舗・メニュー・投稿案のCSV出力、CSV一括登録、全データのバックアップ（JSON） |
| Google仕様設定 | 文字数上限などの仕様値、確認日、公式情報の参照先。値を更新するとチェックにすぐ反映されます |

画面右上の **担当者名** は、更新者として履歴に記録されます。未入力では保存できません。

## データ構造

```
顧客（clients）
└── ブランド・屋号（brands）      … トーン、よく使う表現、避けたい表現、ロゴ、デザインガイド、参考投稿、注意事項
    └── 店舗（stores）           … 店舗ID（ST-00001 形式・自動採番・変更不可）、所在地、営業時間、予約、雰囲気、CTA、確認日・確認元・確認者 など
        ├── メニュー・商品（menu_items） … 名前、説明、価格、販売期間
        └── 投稿案セット（post_sets）    … キャッチコピー、日本語、英語、状態、生成時の入力・事実シート・チェック結果
変更履歴（history）                … すべての作成・更新・削除・複製について、変更前後・更新者・日時を記録
```

- 店舗の所属（ブランド）とブランドの所属（顧客）は、作成後に付け替えられません。別の顧客の情報が混ざるのを防ぐためです。
- ブランド共通の情報と店舗固有の情報が違う場合は、店舗固有の情報を優先します。文章トーンの優先順位は「投稿入力 → 店舗 → ブランド」です。

## 生成の流れ

1. **事実シートを作る**（`src/context.js`）：選んだ1店舗の登録情報と投稿入力だけで作ります。他の店舗の情報は入りません。
2. **生成前の確認**：投稿入力と店舗の登録情報が違う項目（例：登録メニューの価格と入力した価格）があれば、どちらを使うか選ぶまで生成できません。足りない情報も一覧で表示します。
3. **生成**（`src/providers/`）
   - AI生成：Claude に、事実シートだけを根拠にするよう指示し、キャッチコピー・日本語・英語の3つを1セットとしてJSONで受け取ります。画像を添付すると、AIが画像の内容も描写の根拠にします。
   - デモ生成：外部と通信せず、登録情報を定型文に差し込みます。動作確認用で、文章の質はAI生成に及びません。
4. **自動チェック**（`src/validate.js`）：結果を担当者向けの確認欄に表示します。
5. **下書き保存**：投稿案は「下書き → 確認待ち → 承認済み → 使用済み」の状態で管理します。

### 自動チェックの内容

| 区分 | 内容 |
|---|---|
| Google仕様 | 日本語・英語それぞれの文字数が上限（設定値）以内か。本文に電話番号がないか（未確認の連絡先として削除される場合があるため） |
| 事実確認 | 価格・距離・階数・時間など単位付きの数値や、URLが登録情報・投稿入力にあるか。英語版にだけある数値・URLがないか |
| 他店舗の混入 | 別の店舗の店名・住所・予約URL・その店舗にしかないメニュー名が入っていないか |
| 季節表現 | 季節表現を使わない設定なのに季節語がないか。投稿予定日の季節と合わない語がないか（秋葉原のように地名に含まれる字は除外） |
| 表現 | 「＼…／」の見出しがあるか、キャッチコピーの語句が本文で触れられているか、キャッチコピーの長さ、「絶品」「最高」など抽象的な褒め言葉、ブランドの「避けたい表現」、複数案で「〜で味わう」が重なっていないか |

チェックは保存するたびに再実行します。エラーが残ったまま「承認済み」「使用済み」にしようとすると、確認のダイアログが出ます。

## Google公式ガイドラインへの対応

仕様値はコードに書き込まず、`config/google-spec.default.json` に置いています。画面の「Google仕様設定」で更新すると `data/google-spec.json` に保存され、変更履歴にも残ります。

| 項目 | 設定値 | 確認状況 |
|---|---|---|
| 投稿本文の上限 | 1,500文字（最新情報・イベント・特典で共通） | 二次情報で確認 |
| イベントのタイトル | 58文字 | 二次情報で確認 |
| ボタン（CTA） | 予約、オンライン注文、購入、詳細、登録、今すぐ電話 | 二次情報で確認 |
| 画像 | JPG/PNG、10KB〜5MB、最小400×300px | 要再確認 |
| 本文の連絡先 | 電話番号などは削除される場合があり、「今すぐ電話」ボタンが推奨されている | 二次情報で確認 |

> **重要**：開発環境から support.google.com と developers.google.com に直接アクセスできなかったため、上の値は公式ヘルプを引用した二次情報で確認したものです。仕様値は「要再確認」の状態にしてあり、確認欄にもその旨を表示します。運用を始める前に公式ページで確認し、確認日を更新してください。
>
> - [ビジネス プロフィールの投稿を作成、管理する](https://support.google.com/business/answer/7342169?hl=ja)
> - [写真、動画、投稿に関するコンテンツ ポリシー](https://support.google.com/business/answer/7213077?hl=ja)
> - [Business Profile APIs: localPosts](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.localPosts)

文字数は Unicode のコードポイント単位で数えます（絵文字も1文字以上）。日本語本文の目安（700〜1,000文字）とキャッチコピーの目安（24文字）は社内ルールで、Googleの仕様ではありません。

## 使い方

### 顧客・ブランド・店舗を登録する

1. 「顧客・店舗情報」で「＋ 顧客」を押して顧客を登録します。
2. 顧客の横の「＋ブランド」で、ブランドを登録します（トーン、避けたい表現など）。
3. ブランドの横の「＋店舗」で店舗を登録します。保存すると店舗IDが割り当てられ、店舗の画面の下にメニュー・商品の表が出ます。
4. 「情報の確認日・確認元・確認者」を入力します。確認日が90日より前だと、生成時に確認事項として表示します。

まとめて登録する場合は、「CSV・バックアップ」で一度CSVを出力し、同じ列で行を追加して取り込みます。id が空欄の行は新規登録、id がある行は更新になります。1行でもエラーがあれば全件取り消します。登録は「顧客 → ブランド → 店舗 → メニュー」の順に行ってください。

### キャッチコピーと投稿文をセットで生成する

1. 「投稿作成」で店舗を1つ選びます。
2. 投稿目的・テーマ・主役メニュー・伝えたい特徴・価格・CTA・投稿予定日などを入力します。主役メニューを登録メニュー名と同じにすると、価格や販売期間を照合します。
3. 案の数（1案／3案）と、季節表現を使うかどうかを選び、「確認して生成」を押します。
4. 確認画面で、食い違いのある項目はどちらを使うか選び、確認事項を見てから「この内容で生成する」を押します。
5. 案ごとに「画像用キャッチコピー／日本語投稿文／English」が1セットで表示されます。直接編集して「保存」できます。
6. コピーボタンは「キャッチコピー」「日本語投稿文」「英語投稿文」「1セットまとめて」の4種類です。「担当者向け確認」の内容はコピーに含まれません。
7. 内容を確認したら、状態を「確認待ち」→「承認済み」に変え、投稿に使ったら「使用済み」にします。

### 複数店舗に一括で展開する

1. 「投稿作成」で同じ顧客の店舗を複数選びます（別の顧客の店舗は同時に選べません）。
2. 上の入力欄は全店舗共通のキャンペーン情報です。下に出る「店舗ごとの情報」で、店舗ごとに違う主役メニュー・価格・販売期間・特徴・開催日・CTAのURLを入力します。空欄の項目は共通の情報を使います。
3. 生成は店舗ごとに別々に行い、それぞれの店舗の情報だけを使います。住所・営業時間・予約URLは各店舗の登録情報から取ります。
4. 結果は店舗ごと・案ごとに別々のセットとして保存され、個別に編集できます。

## テスト

```bash
npm test          # API・チェック機能・Claude連携のテスト（34件）
npm run test:e2e  # 画面の通し確認（Playwright と Chromium が必要。CHROMIUM_PATH で実行ファイルを指定可能）
```

Claude連携のテストは、手元に立てた疑似APIサーバーに対して実際の SDK で通信し、送信する内容と受け取った結果の扱いを確認します。本物のAPIには接続しません。

## バックアップ

- 画面の「バックアップ（JSON）をダウンロード」で、全データと変更履歴を保存できます。
- サーバーでは `npm run backup` で、データベースを `data/backups/` に日時付きで複製できます。定期的に実行する場合は cron などに登録してください。

## 外部連携と制限

- 外部への通信は、AI生成を使うときの Claude API（Anthropic）だけです。送るのは選んだ店舗の事実シート・投稿入力・添付画像です。
- Googleビジネスプロフィールには接続しません。承認前に外部へ公開されることはありません。
- 認証は `APP_PASSWORD` による共有パスワードだけです。担当者名は自己申告のため、厳密な本人確認にはなりません。
- 添付した画像はAI生成のときだけ使い、保存はしません（ファイル名のみ記録します）。

## 未対応の機能と、次の開発の優先順位

1. **Google仕様の公式確認**：公式ページで仕様値を確認し、`needsReverification` を外す（運用前に必須）。
2. **担当者ごとのログイン**：更新者を確実に記録するため、担当者ごとのアカウントと権限（承認できる人の限定）を追加する。
3. **画像の保存と管理**：ロゴ・デザインガイド・投稿画像をファイルとして保存し、投稿案に紐づける。画像サイズの自動チェックも追加する。
4. **イベント・特典投稿への対応**：タイトル（58文字）、開始・終了日、クーポンコードなどの入力欄とチェックを追加する。
5. **Googleビジネスプロフィールへの投稿（別機能として提案）**：Business Profile API の最新仕様と利用条件（API利用申請、OAuth、店舗の管理権限）を確認したうえで、「承認済み」の投稿案だけを、担当者の操作で送信する機能を検討する。
6. **チェックの精度向上**：形態素解析を使ったキャッチコピーと本文の一致判定、英語版との意味の照合を追加する。
