# 仕様（第1段階：広告レポート作成・議事録タスク整理）

嶋野さんの確認用に、入力項目・計算方法・出力形式・承認手順をまとめます。
アプリ内の「使い方・仕様」画面にも同じ内容（計算式はプログラムの定義から自動表示）があります。

## 1. 広告レポート作成

### 入力項目

| 項目 | 必須 | 備考 |
|---|---|---|
| 店舗・案件 | 必須 | 検索して選択。未選択では承認不可 |
| 配信期間（開始日・終了日） | 必須 | CSVに期間列があれば自動入力（入力済みなら上書きしない） |
| 配信目的 | 推奨 | 認知拡大／フォロワー獲得／プロフィール誘導／サイト・予約ページ誘導／来店・予約獲得／その他。未入力なら良し悪しを判断しない |
| 広告費 | 必須 | |
| リーチ・表示回数・クリック数・プロフィール閲覧数・フォロー数・成果数 | 任意 | 分からなければ空欄。成果数は「何の件数か」を別欄に入力 |
| 追加項目 | 任意 | 保存数など。一覧と報告文に載せるが計算には使わない |
| 前回値 | 任意 | 手入力、または同じ店舗の承認済みレポートから読み込み |

各数値には「出典」（手入力／CSVのファイル名・列名・合算行数／画像ファイル名）と「要確認」フラグが付きます。
画像から転記した値、複数行を合算したリーチは自動で要確認になります。

### 計算方法

| 指標 | 計算式 | 表示 |
|---|---|---|
| クリック単価 | 広告費 ÷ クリック数 | 円・小数第1位 |
| フォロー単価 | 広告費 ÷ フォロー数 | 円・小数第1位 |
| プロフィール閲覧単価 | 広告費 ÷ プロフィール閲覧数 | 円・小数第1位 |
| 成果単価 | 広告費 ÷ 成果数 | 円・小数第1位 |
| CPM（1,000回表示あたりの費用） | 広告費 ÷ 表示回数 × 1,000 | 円・小数第1位 |
| CTR（クリック率） | クリック数 ÷ 表示回数 × 100 | %・小数第2位 |
| フリークエンシー | 表示回数 ÷ リーチ | 回・小数第2位 |
| プロフィール閲覧→フォロー率 | フォロー数 ÷ プロフィール閲覧数 × 100 | %・小数第2位 |
| 前回比 | （今回 − 前回）÷ 前回 × 100 | %・小数第1位 |

- すべて四捨五入。計算結果の横に「広告費 30,000円 ÷ クリック数 600 = 50.0円」の形で使用した数値を表示
- 分母・分子が未入力なら「算出不可（理由）」、分母が0なら算出しない
- 前回比は今回・前回の両方に値がある項目だけ。前回値が無ければ前回比は作らない
- 業界平均などの外部基準は使わない

### 出力

1. 店舗名・広告期間　2. 主要数値の一覧（出典付き）　3. 指標の計算結果（計算式付き）と前回比
4. 数値から読み取れること（所見案、根拠付き、編集可）　5. 次回に向けた改善案（編集可）
6. 店舗へ送る報告文（編集可）　7. 要確認事項

報告文の形式の優先順位：今回レポート画面で指定した形式 → 店舗ごとに登録した形式 → 標準形式。
過去の報告文を貼り付け、数値部分を `{広告費}` `{クリック単価}` `{前回比ブロック}` などの差し込み項目に置き換えて登録します。

要確認事項には次を自動で表示します：未入力の必須項目／要確認フラグの付いた数値／報告文に残った【要確認】／
報告文中の別店舗名／報告文中の入力・計算と一致しない数値／手動編集された報告文。

## 2. 議事録・タスク整理

### 入力

会議名、会議日、参加者（`嶋野成優(Four Seasons), 田中(店舗), 佐藤(デザイナー)` の形式）、関係する店舗（任意）、
文字起こし・メモ（貼り付け、または .txt / .md / .vtt / .srt）。音声は外部でテキスト化してから入力。

### 処理

- 分類の優先順：行頭タグ（`決定：` `未決：` `共有：` `TODO：`）→ 見出し（`■決定事項` 等）→ 語句による判定
- 担当者：「〇〇さんが」「〇〇さんにお願い」、話者の「やります／対応します」から判定。判定できなければ「未設定」
- 区分：参加者の所属が Four Seasons → Four Seasons側、店舗 → 店舗側、それ以外・不明 → その他の担当者
- 期限：日付表記（10/15、10月15日、2026/10/15）は日付に変換。年は会議日から判断し、会議日より2か月以上前になる月日は翌年として要確認。
  「来週中」などの相対表現は日付を確定せず要確認。記載が無ければ「未設定」
- 必要な素材・情報：写真・メニュー表・価格表・ロゴ・見積書などの語を抽出。無ければ「未設定」
- 重複：同じ内容のタスクは1件にまとめ（元の行番号を両方残す）、似ているものは「重複の可能性」として表示

### 出力

1. 議事録の要約　2. 決定事項（＋共有事項）　3. Four Seasons側のタスク　4. 店舗側のタスク
5. その他の担当者のタスク　6. 未決事項・確認事項

## 3. 承認手順（共通）

| 段階 | できること |
|---|---|
| 下書き | 入力・取り込み・編集 |
| 確認待ち | 確認者が内容を確認。「差し戻す」で下書きへ |
| 承認済み | 承認画面で店舗名・区分・要確認事項を表示し、確認チェックを入れて承認。編集不可。「送信用にコピー」が使える |
| 完了 | 手動で送信した後に記録（送信方法メモ可） |

承認後に修正する場合は「修正する（下書きへ戻す）」→ 再度「確認待ち」→「承認」。
すべての操作は利用者名・日時とともに操作履歴に残ります。

## 4. 外部サービス連携

| サービス | 状況 | 代替手段 |
|---|---|---|
| Meta広告マネージャ | 未連携 | CSV書き出し → 取り込み、またはスクリーンショット → 転記 |
| Instagram / LINE / Googleビジネスプロフィール | 未連携 | 承認後にコピーして手動で投稿・送信 |
| Anthropic API（Claude） | 任意（APIキー登録時のみ） | 無効でも手入力・ルール抽出で全機能が使える |

連携を追加する場合は、必要な権限（例：Meta広告のレポート閲覧権限、LINE公式アカウントのMessaging API）と
認証情報の管理方法を先に決めてから実装します。

## 5. 現時点の制約

- データはブラウザごとに保存（複数端末・複数人での同時利用には、共有サーバーの導入が必要）
- 添付画像はその端末にのみ保存され、バックアップには含まれない
- ルールによる議事録抽出は書き方の揺れに弱いため、整理結果は必ず確認・修正が必要
- AI読み取りは実際のAPIキーでの動作確認が未実施
